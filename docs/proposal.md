## 1. Попередня робоча назва проєкту

**UA:** Розробка мікросервісного рішення для управління конфіденційністю за замовчуванням (Privacy by Design) відповідно до вимог GDPR

**EN:** Development of a Microservice-Based Solution for Privacy-by-Design Consent and Data Management Compliant with GDPR

---

## 2. Актуальність та проблематика

Загальний регламент про захист даних (GDPR) встановлює обов'язкові вимоги щодо отримання, фіксації, відкликання та документування згоди користувача (consent), а також щодо реалізації принципів мінімізації даних, обмеження мети обробки та права на видалення. У більшості комерційних систем ці механізми реалізовано фрагментарно та вбудовано в бізнес-логіку конкретного застосунку, що призводить до дублювання коду при масштабуванні на нові юрисдикції, ускладнює комплаєнс-аудит і підвищує ризик розсинхронізації станів згоди між мікросервісами розподіленої системи.

Інженерна складність проблеми полягає в необхідності:

- забезпечити консистентну фіксацію стану згоди користувача в умовах розподіленої архітектури за відсутності глобальних транзакцій, з використанням Saga-подібних механізмів компенсації;
- реалізувати автоматизоване знеособлення персональних даних без порушення цілісності бізнес-процесів через Change Data Capture, а не прямий доступ до чужих схем БД;
- спроєктувати сервіс як підключну (pluggable) точку контролю комплаєнсу (Consent-as-a-Service) для довільної кількості сторонніх мікросервісів без переписування їхньої бізнес-логіки;
- гарантувати відмовостійкість та доставку подій «принаймні один раз» (at-least-once delivery) з ідемпотентною обробкою на стороні споживачів.

Проєкт вирішує інженерну задачу побудови архітектурно ізольованого, відмовостійкого та юридично коректного механізму управління конфіденційністю даних у розподілених системах.

## 3. Сформована ідея продукту

Проєктується мікросервісна платформа управління згодою та життєвим циклом персональних даних (Consent & Data Privacy Management Platform), побудована за принципом Privacy by Design з використанням event-driven архітектури та гарантованої доставки повідомлень.

Система складається з незалежно розгортуваних сервісів, що інкапсулюють: реєстрацію та зберігання згод, обробку DSAR-запитів через Saga-оркестрацію, автоматизоване знеособлення на основі CDC, незмінне аудит-логування та уніфікований API Gateway для інтеграції зі сторонніми бізнес-сервісами.

---

## 4. Детальний опис функціоналу (Core Features)

1. **Consent Management Service** — реєстрація, зберігання та версіонування згод (мета обробки, категорія даних, термін дії) з повним журналом історії змін.
2. **DSAR Processing Engine** — обробка запитів на доступ, виправлення, видалення та експорт даних, реалізована як хореографічна Saga з компенсуючими транзакціями між сервісами.
3. **Consent Propagation Bus** — event-driven поширення змін стану згоди через брокер повідомлень (Kafka/RabbitMQ) з ідемпотентними споживачами та Dead Letter Queue для необроблюваних подій.
4. **Automated Anonymization Module** — знеособлення персональних даних у сторонніх БД через Change Data Capture (Debezium) за визначеними політиками зберігання, без прямого доступу до чужих схем.
5. **Consent Management SDK** — клієнтська бібліотека для інтеграції сторонніх сервісів без зміни їхньої доменної логіки, покрита contract-тестами (Pact).
6. **Audit & Compliance Logging** — незмінний журнал аудиту всіх операцій з персональними даними для регуляторної звітності.
7. **Admin & DPO Dashboard** — панель для Data Protection Officer із візуалізацією статусів згод, DSAR-запитів та метрик комплаєнсу.
8. **API Gateway** — єдина точка входу з автентифікацією (OAuth2/JWT) та rate limiting для захисту комплаєнс-шару.

## 5. Попередній інструментарій та технологічний стек

**Мови програмування:** TypeScript, SQL

**Архітектурні патерни:**
- Мікросервісна архітектура (Domain-Driven Design, database per service)
- Event-Driven Architecture з гарантованою доставкою (Outbox Pattern + Kafka/RabbitMQ)
- Saga Pattern (хореографічний) для розподілених DSAR-транзакцій
- API Gateway з автентифікацією та rate limiting
- Change Data Capture (Debezium) для анонімізації без прямого доступу до чужих БД

**Фреймворки та бібліотеки:** NestJS, Consent Management SDK, Pact (contract testing)

**Бази даних:** PostgreSQL (primary-replica реплікація), Redis (кешування)

**DevOps-інструменти:** Docker/Docker Compose, Kubernetes, GitHub Actions (lint → test → build → security scan → deploy), Prometheus/Grafana
